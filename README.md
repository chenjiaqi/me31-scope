# me31-scope

ME31-XDXX0400 四通道 PT100 温度采集上位机。通过 RS485 / Modbus RTU 读取温度，实时绘制曲线，
并可将温度、时间戳与当时的通道偏移值记录成 CSV。

## 功能

- 自动枚举本机串口，波特率/校验位/数据位/停止位可配（默认 9600 8N1，从站地址 1）
- 每秒轮询一次四个通道的温度；传感器断线显示为 `--`，曲线上留空不连线，不会画出假数据
- 每个通道可单独设置温度漂移（偏移）值，写入后回读校验，失败时给出具体原因（超时 / 设备异常码 / 值不符）
- 实时曲线：数据未填满窗口时自左向右生长，填满后随新数据整体左移；Y 轴按可见范围自适应
- 「开始记录」把时间（毫秒精度）+ 四通道温度 + 当时的偏移值写入 CSV，每行即时落盘，中途崩溃不丢已写数据
- 「通信日志」面板显示收发帧，便于现场排查接线、从站地址与校验位问题

## 设备协议要点

| 项目 | 寄存器 | 说明 |
| --- | --- | --- |
| 温度（整数） | `0x0190` | 输入寄存器，FC04，值 / 10 = ℃，16 位有符号补码 |
| 温度（浮点） | `0x01C2` | 输入寄存器，占 8 个寄存器 |
| 温度漂移 | `0x2328` | 保持寄存器，FC03/06，值 / 10 = ℃，范围 −10.0 ~ +10.0 |
| 传感器断线 | — | 读回 `0xFC19`（有符号 −999），上位机当作无效值 |
| 从站地址 | `0x07E8` | |
| 设备重启 | `0x07EA` | 写入触发 |

两个容易踩的坑：

1. 设备内部已经把偏移值叠加进温度了，所以上位机直接显示读回值，不再做二次补偿。
2. FC06 的成功响应与请求字节完全相同。上位机不能按「回显」把它丢掉，否则会误判为超时失败。

## 开发

需要 Python 3.13+ 和 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync             # 安装依赖
uv run me31-scope   # 启动程序
uv run pytest -q    # 运行测试（67 项）
```

`tests/test_client.py` 用 pty 伪终端模拟设备收发，只在 POSIX 上运行，Windows 下自动跳过（10 项），
其余测试跨平台通用。

## 打包

### GitHub Actions（推荐）

推送到 `main` 或推 `v*` 标签会触发 `.github/workflows/build-windows.yml`，在 `windows-latest` 上
依次跑测试、打包、启动冒烟测试，产物 `me31-scope-windows-x64` 在 Actions 页面下载。
也可以在 Actions 页面手动 Run workflow。

### 本机 Windows 打包

PyInstaller 不支持交叉编译，Windows 包只能在 Windows 上构建：

```bat
uv sync --frozen
uv run --with pyinstaller pyinstaller packaging\me31_scope.spec --noconfirm --clean
```

产物是 `dist\me31-scope\` 整个目录，拷到目标机器双击 `me31-scope.exe` 即可运行，目标机器无需安装 Python。
